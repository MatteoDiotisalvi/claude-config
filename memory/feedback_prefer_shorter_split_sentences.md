When a sentence being drafted starts accumulating multiple comma-joined clauses (main claim + explanation + consequence/exception all in one), prefer splitting it into two shorter sentences instead. Not a strict rule — short sentences that are naturally single-clause don't need forcing apart — but default to splitting once a sentence would otherwise run long.

**Broadened 2026-08-21, while drafting Related Work for [[the-verifier-that-cannot-see]]:** the user asked to generalize this beyond sentence length alone — prioritize clarity and legibility as a standing goal across all stylistic choices, not just clause-splitting. This covers plain word choice over inflated/nominalized phrasing, straightforward syntax over embedded subordinate clauses, and avoiding constructions that are technically correct but require rereading to parse — even when a more "elegant" or dense alternative is available.

**Why:** Originally said explicitly while drafting the Methodology section of [[matteo-diotisalvi-ai-trading-paper]], after several rounds of sentence options (and the user's own edits) trended toward long, multi-clause sentences stacking a main point with its justification and a caveat all in one breath. The dyslexia/dysgraphia accessibility context surfaced again during the Introduction session for [[the-verifier-that-cannot-see]] (see HANDOFF_LITERATURE.md Section 8) — treat this as a real accessibility consideration, not just a stylistic nicety.

**How to apply:** When proposing phrased sentence options, check length/clause-count before presenting them; if a single sentence is doing three jobs (state + explain + qualify), default to offering the two-sentence split as at least one option. Beyond splitting, also default toward the plainer, more directly parseable phrasing among otherwise-equivalent options — this is a standing tiebreaker across all future academic writing sessions with this user, not specific to one paper.
