When asked how much to optimize for speed versus thoroughness on a
research or analysis task, Matteo said explicitly: "time is also not a
constraint in this project I prefer things done well than quick, make
this a universal rule."

**Why:** Stated directly while setting up the [[project-trading-m4chronix]]
research, where getting it wrong has real financial and reputational cost
for him, but he framed it as a universal rule, not scoped to that one
project.

**How to apply:** Default to doing thorough, well-verified work over fast
work when the two trade off against each other, across projects, unless
he gives an explicit deadline or says speed matters for a specific task.
Don't use this as license to pad work with unnecessary steps, but don't
cut corners (skipping verification, using a single source, rushing to a
conclusion) to save time either.
